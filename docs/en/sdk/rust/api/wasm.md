# Rust — WASM / Web (Preview3)

> **This page describes the planned WASM integration for Preview3. `nnrp-ffi` can be compiled as raw WASM, but browser-ready WASM bindings are not yet available; the browser/Node transport adapter and wasm-bindgen surface have not landed yet.**

---

## Build Commands

```bash
# Install wasm-pack
cargo install wasm-pack

# Build WASM package (targeting bundlers like webpack/vite)
wasm-pack build nnrp-ffi --target bundler --out-dir pkg/bundler

# Build for direct browser (ES module)
wasm-pack build nnrp-ffi --target web --out-dir pkg/web

# Build for Node.js
wasm-pack build nnrp-ffi --target nodejs --out-dir pkg/node
```

The raw `nnrp_ffi.wasm` artifact is not a complete npm package. Browsers cannot load native `.dll` / `.so` / `.dylib` libraries, so the JS/TS SDK must ship `.wasm`, generated JS glue, `.d.ts` declarations, and browser transport adapters.

## Planned TypeScript Interface

```typescript
// Generated by wasm-bindgen / wasm-pack (Preview3)

export interface NnrpClientConfig {
    maxViews?: number;
    enableCache?: boolean;
    transportPolicy?: "auto" | "prefer_quic" | "prefer_tcp";
}

export interface NnrpSubmitRequest {
    frameId: number;
    tileIds: Uint16Array;
    sections: NnrpTensorSection[];
    budgetPolicy?: number;
    inferenceBudgetMs?: number;
}

export interface NnrpResult {
    frameId: number;
    resultClass: "complete" | "partial" | "stale_reuse" | "degraded";
    inferenceMs: number;
    sections: NnrpTensorSection[];
}

export declare class NnrpWasmClient {
    static connect(url: string, config?: NnrpClientConfig): Promise<NnrpWasmClient>;
    openSession(): Promise<NnrpWasmSession>;
    close(): Promise<void>;
}

export declare class NnrpWasmSession {
    submit(request: NnrpSubmitRequest): Promise<NnrpResult>;
    submitNowait(request: NnrpSubmitRequest): Promise<void>;
    awaitResult(frameId: number): Promise<NnrpResult>;
    cancelFrame(frameId: number): Promise<void>;
    close(): Promise<void>;
}
```

## Web App Integration Example

```typescript
import init, { NnrpWasmClient } from "@nnrp/sdk-wasm";

await init();

const client = await NnrpWasmClient.connect("wss://render.example.com:4433");
const session = await client.openSession();

const result = await session.submit({
    frameId: 1,
    tileIds: new Uint16Array([0, 1, 2, 3]),
    sections: [tileSection],
    budgetPolicy: 0x01, // AllowPartial
    inferenceBudgetMs: 50,
});

console.log(`Result class: ${result.resultClass}, inference=${result.inferenceMs}ms`);
```

## WASM Limitations

| Item | Note |
|---|---|
| Transport | WebSocket or WebTransport (no raw TCP/UDP in browsers) |
| Thread model | Single-threaded WASM; async via JS Promise |
| Shared memory | Not supported cross-origin |
| Max body size | Limited by browser memory |
| QUIC | WebTransport only (requires HTTPS origin) |

### Offloading to a Web Worker

```js
// worker.js
import init, { NnrpWasmClient } from '/pkg/nnrp_wasm.js';
await init();
const client = await NnrpWasmClient.connect(ENDPOINT);
self.onmessage = async ({ data }) => {
    const result = await client.openSession().then(s => s.submit(data));
    self.postMessage(result);
};
```

## Common Pitfalls

::: warning
1. **WASM cannot use raw TCP/UDP.** Use WebSocket or WebTransport only — do not attempt raw socket access.

2. **Transferring an `ArrayBuffer` to a Worker transfers ownership.** `slice()` first if the main thread still needs the data.

3. **The `.js` and `.wasm` files from `wasm-pack build --target web` must be deployed together** and served from the same origin.

4. **The current WASM package is a Preview3 placeholder.** The API shape is not yet finalized; do not depend on the current interface in production.
:::
